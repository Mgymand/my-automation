# v8セッション 通知対応ガイド

> Claude Code が 5 回通知を送ります。各通知への対応手順です。

---

## 通知の仕組み

Claude Code は `docs/session_v8/notifications/Nn_xxx.md` ファイルを作成して通知します。
岩本様は該当ファイルを開き、指示された形式で回答を追記してください。

回答後、Claude Code はファイル変更を検知して続行します。
待機時間内に回答がない場合、デフォルト方針で自動続行します（放置可能）。

---

## N1: ブランチ統合方針の最終確認

**タイミング**: セッション開始 60 分後
**待機時間**: 30 分
**放置時のデフォルト**: frosty-swartz 上で再実装

### 対応手順

ファイル `docs/session_v8/notifications/N1_branch_integration.md` を開き、
Claude Code が作成したレポートを確認。

- 方針に同意 → ファイル末尾に `Yes` と追記して保存
- 方針を変更したい → 変更内容を記述して保存
- 放置 → 30分後に自動続行

**推奨**: Yes（前回の議論で確定済みのため）

---

## N2: Salesforce 認証情報の確認

**タイミング**: M1 実接続テスト直前（セッション開始 8〜9 時間後想定）
**待機時間**: 60 分
**放置時のデフォルト**: モックモードで続行（実接続スキップ）

### 対応手順

Render Dashboard で以下を確認：
- `SF_CLIENT_ID` が設定されているか
- `SF_PRIVATE_KEY_PATH` が設定されているか（Secret Files に鍵ファイルがあるか）
- `SF_USERNAME` が設定されているか
- `SF_MOCK_MODE` を `false` に変更

変更後、ファイル `docs/session_v8/notifications/N2_sf_auth.md` に：
- 認証情報設定済み → `OK`
- 未設定 → `未設定`

**Salesforce 接続済みアプリの作成手順**（別途案内します）：

1. Salesforce Setup > アプリケーションマネージャー
2. 「新規接続アプリケーション」
3. OAuth 設定を有効化
4. コールバック URL: `https://login.salesforce.com/services/oauth2/success`
5. スコープ: api, refresh_token, offline_access
6. デジタル署名の使用: オン、証明書アップロード
7. 作成後 Consumer Key (Client ID) を取得
8. 「OAuth ポリシー」で事前承認済みユーザーに設定

---

## N3: ダミーユーザー確認

**タイミング**: M7 マルチユーザー実装完了時
**待機時間**: 30 分
**放置時のデフォルト**: ダミーユーザーのまま続行

### 対応手順

Claude Code が作成した3ユーザーの一覧が通知ファイルに記載されます。
本番運用したい実ユーザーがいれば、ファイルに以下の形式で追記：

```
追加ユーザー:
- 名前: 田中太郎, メール: tanaka@lime-fit.com, ロール: member
- 名前: 佐藤花子, メール: sato@lime-fit.com, ロール: manager
```

保存後、Claude Code が反映します。

放置すればダミーのまま続行、次セッションで差し替えも可能。

---

## N4: 設計判断要求（複数回の可能性あり）

**タイミング**: 予期せぬ判断が必要になった時
**待機時間**: 各 30 分
**放置時のデフォルト**: Claude Code が提示したA案

### 対応手順

通知ファイルを開き、状況と選択肢を確認。
希望する選択肢をファイルに追記。

**判断基準の目安**:
- 時間のかかる選択肢 → 次セッション送り
- コスト超過の選択肢 → 却下
- 既存機能を壊す選択肢 → 却下

---

## N5: 完了報告

**タイミング**: セッション終了時（11〜12時間後）
**待機時間**: なし
**対応**: レポート確認のみ

### 対応手順

`docs/session_v8/notifications/N5_completion.md` および
`docs/session_v8/00_session_summary.md` を確認。

特に以下を確認：
- 既存 30+ 機能が維持されているか
- 本番デプロイが成功しているか
- コスト実測値が予算内か
- 次セッション優先事項に異議がないか

問題があれば、次セッション（v9）のプロンプトに反映するため、Web の Claude に共有してください。

---

## 緊急時の対応

### Claude Code が止まらない
セッション開始から 12 時間以上経過しても動いている場合：

```
タイムボックスを超過しています。フェーズF（引継ぎシート作成）に即座に移行し、
現時点の成果物を保存してセッションを終了してください。
```

### 本番デプロイで問題発生
`docs/session_v8/07_rollback_plan.md` を開き、ロールバック手順に従う。
不明な場合は Web の Claude に共有して指示を仰いでください。

### コストが想定を大幅超過
Anthropic Console で使用量確認。
¥2,000 超えた時点で Claude Code に以下を送信：

```
コスト上限到達。Sonnet 使用を即停止、Haiku 限定モードに切替。
残り作業は最小限にして引継ぎシート作成へ。
```

| 通知 | 所要時間 |
|------|--------|
| N1 | 2 分（Yes 追記） |
| N2 | 5〜60 分（SF準備状況による） |
| N3 | 5 分（ユーザー確認） |
| N4 | 5 分 × 最大3回 = 15 分 |
| N5 | 10 分（レポート確認） |

**合計: 37〜92 分**（SF準備に時間がかかる場合）
