# 模倣優先モード（既存の勝ち投稿の型を再現する）

2026-11 の方針: **オリジナルの手法ではなく、X で実際に成果が出ている FANZA アフィ投稿の内容・掲載方法を、できる限り忠実に再現する。**
既定は `REPLICATION_MODE=strict` です。自前の訴求軸（A〜E の 5 案）は、再現できる型が無い商品のときだけ使う予備になります。

## 1. 何を再現し、何を再現しないか

| 再現する（形式・方法） | 再現しない（他人の表現・素材） |
|---|---|
| 行構成と各行の役割（1 行目に割引率と価格、2 行目に作品名 …） | 1 つのアカウントにしか無い言い回し |
| 数字の種類と置き場所（割引率・価格・通常価格→現在価格・期限・レビュー件数） | 他人の画像・動画（素材は DMM 公式のみ） |
| 業界の定型句（「詳細はリプ欄」「配信開始」「セール中」など） | アカウント名・アイコン・キャラクター |
| 3 アカウント以上が使っている語句 | 元投稿の作品名・数字そのもの（自分の商品の事実に置き換える） |
| 記号・絵文字の使い方、汎用ハッシュタグ（#FANZA など） | 個人的なハッシュタグ |
| リンクの置き場所（本文末 / リプ欄）、メディア種別（画像 / 動画）、投稿時刻 | 存在しない期限・順位・割引・新作表記 |

右の列を再現しない理由は 3 つあります。
- **著作権**: 文章や画像の複製は他人の著作物の利用になります。形式・構成・アイデアは保護されません
- **X のルール**: 他人の投稿の複製や、同一文面の量産は、スパム / なりすまし扱いで表示が抑えられます。利益が下がります
- **景品表示法**: 自分の商品に当てはまらない「半額」「本日まで」「新作」「ランキング 1 位」は不当表示になります。【PR】表記も必須です

## 2. 仕組み

```
公開投稿（X READ の検索 / 調査 CSV）
  └─ 骨格化: 数字・作品名・女優名・ジャンル・日付・主張をスロットに置換し、定型句だけ文字として残す
       例）「50%OFF｜1,980円→990円 / 「作品名」 / 人妻／〇〇さん / 9/30 23:59まで / リプ欄から #FANZA」
         → ⟦DISC⟧｜⟦LIST_PRICE⟧→⟦PRICE⟧ / 「⟦TITLE⟧」 / ⟦GENRE⟧／⟦ACTRESS⟧さん / ⟦END_DATE⟧ ⟦END_TIME⟧まで / リプ欄から #FANZA
  └─ 同じ骨格を束ねて採点: スコア = 成果 ×（0.5 + 0.5 × 再現性）× 忠実度
       成果   : 外れ値スコア（フォロワーに対する表示回数・エンゲージメント率）の相対値
       再現性 : その骨格を使っているアカウント数（3 アカウントで満点）。1 人だけの成功は偶然の可能性がある
       忠実度 : 元投稿のうち型として再現できる割合。半分以上が固有の言い回しの投稿は、文章力で伸びたものとして除外
  └─ 自分の商品の事実で埋める（下の表）。埋められないスロットがある骨格は、その商品には使わない
  └─ 元投稿との類似度が 0.6 以上なら使わない（同じ作品・同じ数字で同文になるのを防ぐ）
  └─ 骨格ごとに Pattern（SK_…）を登録 → 自分の投稿の売上・エンゲージ・表示で Thompson Sampling が勝ち骨格へ寄せる
```

| スロット | 埋める事実 | 事実が無いとき |
|---|---|---|
| ⟦PRICE⟧ / ⟦LIST_PRICE⟧ / ⟦DISC⟧ | FANZA API の現在価格 / 通常価格 / 割引率 | その骨格を使わない |
| ⟦END_DATE⟧ ⟦END_TIME⟧ | API のキャンペーン終了日時 | 使わない（期限を作らない） |
| ⟦REL_DATE⟧ | 配信日 | 使わない |
| ⟦RAVG⟧ ⟦RCOUNT⟧ | レビュー平均・件数（5 件以上） | 使わない |
| ⟦RANK⟧ ⟦DURATION⟧ ⟦COUNT⟧ | 確かめられないため常に未使用 | 使わない |
| 「半額」「本日まで」「新作」「セール中」など | 割引 50% 以上 / 本日終了のキャンペーン / 配信 7 日以内 / 割引中 | 使わない |
| 「最安値」「独占」など | 確かめられない | 使わない |
| ⟦TITLE⟧ | 作品名（長すぎれば省略） | — |
| ⟦ACTRESS⟧ ⟦GENRE⟧ | 出演者・ジャンル | その部分だけ省く |
| ⟦FREE:n⟧（元投稿の固有表現） | 文字としては再現しない。Anthropic API があれば商品データだけで n 字程度の句を作って埋める | 省く。行の半分以上が FREE の行は落とす |

## 3. 掲載方法の再現

- **リンクの置き場所**: 元投稿の多数派に合わせる。本文末に置いて伸びている型なら「Affiliate URL は本文の最後」、そうでなければ「投稿後すぐリプでリンク」と各投稿の指示に出る
- **メディア**: 元投稿の多数派（画像 / 動画）に合わせて DMM 公式素材を選ぶ
- **投稿時刻**: 調査投稿のうち成果が高いものほど重く数えた時刻分布を事前分布にし、自分の実績で更新する
- **ハッシュタグ**: 元投稿の汎用タグ（#FANZA 等）だけを残す
- **参考投稿**: 各投稿に、再現元の投稿 ID を「類似成功投稿」として添える（X で開いて形を確認できる）

## 4. データの集め方と費用

型の元データは、伸びている他アカウントの公開投稿です。
- **推奨: X READ（Bearer Token）**。毎週 8 クエリ × 100 件を検索します。2026-09 時点の従量料金（1 件 0.005 ドル）で週 4 ドル程度です。`research --per-query 50` で半分にできます
- **代わり: 調査 CSV**。伸びている投稿を見つけたら、`x_post_id,followers,text,media_type,created_at,views,likes,reposts,replies,bookmarks` の CSV を運用リポジトリの `inbox/` に置きます。取り込みと型の作り直しは自動です
- どちらも無い間は、2026-09 の公開調査で観測した 8 つの型（セール速報・激安・女優・新作・掘り出し・動画・短文）で動きます。実データの型が入ると、成果の高い順に置き換わります

## 5. コマンド

```bash
python -m affiliate_bot replicate                    # 調査投稿から型を作り直して一覧
python -m affiliate_bot replicate --list --limit 20  # 型の一覧（スコア・アカウント数・リンク位置・メディア）
python -m affiliate_bot replicate --preview CONTENT_ID  # その商品に使える型を事実で埋めて表示
```

`REPLICATION_MODE` は次の 3 つです。
- `strict`（既定）: 型を再現した案を最優先し、自前の案は 0.3 倍に下げる
- `mixed`: 自前の案を 0.8 倍に下げる
- `off`: 再現しない
